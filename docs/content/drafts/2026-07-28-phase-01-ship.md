# I renamed one type and the whole product got clearer

**Publish date:** 2026-08-01

Nucleus used to store an "Idea" — a string in localStorage. It now stores a
"Venture" — a thing with a lifecycle, a stage, and a history. Same button,
same UI. Different noun underneath.

**Where it stands:** ventures live in JSON files on disk (`.nucleus/`), not
the browser. Eight stages: `captured → validated → planned → building →
launched → growing`, plus `killed` and `archived` as real, terminal outcomes
— not error states.

**The problem:** "idea" is a string. A studio that "builds businesses, not
apps" can't be built on a string — there's nowhere to hang a verdict, a plan,
or a kill decision.

**How it works now:** every stage change goes through one function that
checks a transition table before writing anything.

```ts
export function assertTransition(from: Stage, to: Stage): void {
  if (!canTransition(from, to)) {
    throw new Error(`Illegal stage transition: ${from} -> ${to}`);
  }
}
```

`killed` is only reachable from `captured` or `validated` — you can't kill a
venture that's already shipped, and once something is `archived` there's no
path back out. The API never writes `stage` directly; it always goes through
`advance()`, so this table is the only place that decision lives.

**The call I made:** kept storage as plain JSON files instead of standing up
Supabase, which the original plan called for. A file the user can open, back
up, and delete *is* "your own computer, under your own control" — a hosted
Postgres row isn't, no matter how good the free tier is.

**Next:** the AI gateway gets its first real task — turning a captured
venture into an actual verdict.
