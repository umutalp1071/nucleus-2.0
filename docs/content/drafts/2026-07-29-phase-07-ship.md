# Nucleus doesn't write your code. It writes the brief that does.

**Publish date:** 2026-08-13

Every AI app builder I've tried ends the same way: "here's your app." Nucleus ends with a document instead, on purpose.

**Where it stands:** planned ventures now have a Build stage. Milestones become checkable tasks with a progress bar, and a `generate-build-spec` task turns the plan into a handoff artifact: user stories with acceptance criteria, a data model, screens, an explicit out-of-scope list, and the literal first commit to write. One "Copy for..." control renders it three ways.

**The problem:** the scope decision from day one was that Nucleus validates, plans, and scopes an MVP -- it never generates the user's application code. But a validated plan sitting in a JSON file is still zero lines of a working product. Something has to carry it across that seam without quietly becoming a code generator.

**How it works now:**

```ts
const BuildSpecSchema = z.object({
  summary: z.string(),
  userStories: z.array(storySchema).min(3).max(10),
  dataModel: z.array(entitySchema),
  screens: z.array(screenSchema),
  outOfScope: z.array(z.string()).min(3),
  firstCommit: z.string(),
});
```

**The call I made:** I rejected building any integration for the "where is this being built" link -- no OAuth, no repo webhooks, just a plain text field. And I didn't just format the agent-brief version and ship it: I pasted a real generated brief into a coding-agent session first. The first draft named "auto-organizes" as a feature but never said by what rule, and defined a `User` entity with no sign-in screen. Both are now required in the prompt.
