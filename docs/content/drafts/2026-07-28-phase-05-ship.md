# Bring your own key. I never see your data or your bill.

**Publish date:** 2026-08-09

Nucleus now has a real Settings page, and the design constraint underneath it
is simple: I should never be in a position to see your OpenRouter key, your
spend, or your ideas.

**Where it stands:** paste an OpenRouter key, it's tested with one real
minimum-cost call before saving, and the whole app switches from demo mode to
live analysis with no restart. Budget caps are editable and take effect on
the very next request. A spend breakdown shows cost by task, by venture, and
a 30-day trend -- and the "Your data" panel prints the exact folder path on
your disk where everything lives.

**The problem:** most "AI settings" pages either hide the key handling behind
vague trust, or overcorrect into security theater. I wanted the actual
guarantee to be checkable, not just claimed.

**How it works now:** the settings API returns a redacted preview, never the
key itself --

```ts
return NextResponse.json({
  hasKey: apiKey !== null,
  keyPreview: apiKey ? redactKey(apiKey) : null, // "sk-or-...7890", never the full string
  ...
});
```

-- and I verified it, not just wrote it: `grep -ri "sk-or-" .nucleus/*.json`
finds the key in exactly one file, and it's nowhere in any log line across
the session.

**The call I made:** BYOK isn't a checkbox feature here, it's the whole
economic model. Zero marginal cost to me means zero incentive to ever push
you toward using more tokens than you need.
