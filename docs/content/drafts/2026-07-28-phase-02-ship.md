# My AI budget cap runs before the request, not after

**Publish date:** 2026-08-03

Every model call Nucleus will ever make — now and in every future feature —
goes through one function. It checks the budget before it checks anything
else.

**Where it stands:** `runTask()` is live: three model tiers (cheap/mid/
frontier), automatic downgrade when budget is tight, Zod validation on every
response with one repair retry, a 7-day cache keyed on the exact
(task, model, prompt) tuple, and a mock provider that makes the whole thing
work with zero API keys.

**The problem:** a budget you check after the call already happened isn't a
budget. It's a receipt.

**How it works now:** the gateway resolves a tier against the budget guard
*before* it ever touches the provider.

```ts
for (;;) {
  const estimated = estimateCost(tier, prompt.length, task.expectedOutTokens);
  const decision = await budget.preflight(estimated, budgetOpts);
  if (decision.decision === "ok") break;
  if (decision.decision === "downgrade") { tier = nextTierDown(tier); continue; }
  return { ok: false, reason: "budget_exceeded", message: ... };
}
```

The single most important test in the whole file asserts the provider's call
count is exactly **zero** after a block.

**The call I made:** cache keys use the *resolved* tier's model, not the
task's preferred one. If budget forces a downgrade to a cheaper model, that
answer only gets cached under the cheap-tier key — so once budget recovers, a
fresh request still gets the better model instead of silently replaying a
downgraded answer forever.
